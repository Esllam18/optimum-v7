# قائمة ما قبل نشر الدخول والحسابات

تم تنفيذ التطبيق والـBackend، لكن قبل فتح النظام على نطاق عام راجع إعدادات Supabase Auth التالية من لوحة المشروع:

1. عطّل **Allow new users to sign up** لمزوّد Email حتى لا يستطيع أي شخص إنشاء حساب مباشرة عبر Auth API. إنشاء المستخدمين من Admin API داخل `identity-provisioning` سيظل هو المسار المعتمد.
2. اضبط **Site URL** على رابط تطبيق الشركات الحقيقي.
3. أضف روابط الاستعادة المسموحة إلى **Redirect URLs**، مثل:
   - رابط تطبيق الشركات الإنتاجي.
   - `http://localhost:4173` للاختبار المحلي فقط.
4. استخدم HTTPS ونطاقين منفصلين عند النشر، مثل:
   - `app.example.com` لتطبيق الشركات.
   - `platform.example.com` للوحة الإدارة الخاصة.
5. اضبط `OPTIMUM_CLIENT_APP_URL` في خادم لوحة المنصة على رابط تطبيق الشركات.
6. للإرسال التلقائي لبيانات الدخول، أضف Secrets:
   - `RESEND_API_KEY`
   - `OPTIMUM_FROM_EMAIL`
   - `OPTIMUM_CLIENT_LOGIN_URL`
7. اختبر ثلاث رحلات بحسابات اختبار:
   - إنشاء شركة ومالك جديد.
   - أول دخول وتغيير كلمة المرور.
   - إنشاء عضو وتعديل صلاحياته وإعادة إصدار كلمة مرور مؤقتة.
8. فعّل حماية كلمات المرور المسرّبة من إعدادات Auth قبل الإنتاج.

هذه الإعدادات تخص بيئة الاستضافة وليست أسرارًا أو إعدادات يجب وضعها في كود المتصفح.
